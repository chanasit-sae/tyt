How to use this guide

This course teaches you to control a microcontroller by writing directly to its registers — no library magic. Every lab follows the same rhythm, and once you internalize it, every assignment becomes fill-in-the-blank.

The one pattern behind every lab
  1. Turn on the clock for the peripheral (RCC enable bit) — nothing works without this.
  2. Configure the pin (GPIO mode: input / output / alternate / analog).
  3. Configure the peripheral (UART baud, ADC channel, EXTI edge…).
  4. Use it — either by polling a flag in a loop, or by interrupt (Ch 5).
Study strategy Read a chapter overview → study the register table → read the lab code line by line and predict each blank before looking at the answer. The exam blanks are the same registers you fill in the labs.

The golden rule of multi-bit fields To set a 2-bit or 4-bit field, clear it first, then set it — otherwise old bits linger and corrupt the value: 
GPIOA->MODER &= ~(0b11 << (pin*2));   // 1. clear the field
GPIOA->MODER |=  (0b10 << (pin*2));   // 2. set new value
For single-bit fields (like ODR) you can just |= to set, &= ~ to clear, ^= to toggle.

Chapter 0 — Foundations

Before touching a register you need the mental model of what a microcontroller is.

CPU, memory, and peripherals

An embedded system is a computer built into a device to do one job. Inside the MCU:

  • CPU (Cortex-M4) — executes instructions from Flash. Default clock 16 MHz.
  • Flash (512 KB) — non-volatile; holds your program (ROM-like).
  • SRAM (128 KB) — volatile; holds variables at runtime.
  • Peripherals — hardware blocks (GPIO, UART, ADC, timers…) that the CPU controls through registers.
  • Buses (AHB/APB) — connect the CPU to peripherals; each peripheral hangs off a specific bus, which is why its clock lives in a specific RCC register.

Memory-mapped I/O

Core idea Every peripheral register is just a memory address. Writing to that address changes hardware; reading it senses hardware. That's why controlling an LED looks like writing to memory: GPIOA->ODR |= (1<<5);

The CMSIS header stm32f4xx.h maps friendly names onto those addresses. GPIOA is a pointer to a struct laid out exactly like the register block, so GPIOA->MODER resolves to address 0x40020000.

Bit manipulation — the essential toolkit

Exam favorite You will be asked to fill in bit operations. Memorize: |= set, &= ~ clear, ^= toggle, & test.

Chapter 1 — GPIO (Digital Input/Output)

GPIO = General-Purpose Input/Output. These pins read buttons and drive LEDs. This chapter establishes the 4-step pattern used forever after.

Step 1 — Clock gating (RCC)

#1 cause of "my code does nothing" Peripherals boot with their clock off to save power. Writing to a peripheral register before enabling its clock silently does nothing. Always enable first: 
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;   // turn on GPIOA

Step 2 — GPIO registers

See the cheat-sheet for the full table. The one you configure first is always MODER.

MODER values (2 bits per pin) 00 Input 01 Output 10 Alternate function 11 Analog

Lab 1.2 — Output: blinking an LED

Blue LED is on PA5. Set PA5 as output, then toggle ODR in a loop with a delay.

// 1. clock
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
// 2. PA5 as output (clear then set)
GPIOA->MODER &= ~GPIO_MODER_MODER5;
GPIOA->MODER |= (0b01 << GPIO_MODER_MODER5_Pos);
while(1){
    GPIOA->ODR ^= GPIO_ODR_OD5;   // toggle
    DELAY_SEC;                     // software delay
}
Software delay A busy for-loop wastes cycles counting. The slides count ~12 machine instructions per iteration and wrap it in a DELAY_SEC macro. It "works" but blocks the CPU — remember this pain; Ch 5 (interrupts) fixes it.

Labs 1.3/1.4 — Input & pull-up/pull-down

Read a button through IDR (input data register, read-only). A floating input pin picks up noise, so you must tie it with an internal resistor via PUPDR.

Lab 1.5 — Polling & the danger of blocking

Polling = repeatedly checking a condition in a loop. Simple, but if the loop contains a blocking function (like a long delay), the CPU can't do anything else.

Why blocking is dangerous
  • Missed deadlines — you're stuck delaying while a real event happens.
  • Watchdog (WDT) resets — a stuck loop can trip the watchdog.
  • High power — the CPU spins at full speed doing nothing.
This motivates interrupts in Chapter 5.

The register-definition file

Instead of raw addresses, the labs use CMSIS. Two lines unlock it:

#define STM32F411xE
#include "stm32f4xx.h"
  • Access a register: PERIPHERAL->REGISTER e.g. GPIOA->MODER
  • Bit mask macro: PERIPHERAL_REGISTER_BITNAME e.g. GPIO_MODER_MODER5
  • Bit position macro: append _Pos e.g. GPIO_MODER_MODER5_Pos
Reading the naming GPIO_ODR_OD5 = the mask for output-data bit 5. << ..._Pos shifts your value to the right place. Use the plain mask to set/clear a whole field, use _Pos when writing a specific value into a multi-bit field.

Chapter 3 — UART (Serial Communication)

UART = Universal Asynchronous Receiver/Transmitter. It's how the board talks to your PC over the USB cable. Serial (one bit at a time) and asynchronous (no shared clock — both sides just agree on speed).

Frames, baud rate & the physical link

  • Two wires: Tx (transmit) and Rx (receive). Tx of one device → Rx of the other.
  • A frame = Start bit (0) + 5–9 data bits + optional parity + Stop bit(s) (1 / 1.5 / 2).
  • Data is sent LSB first.
  • Baud rate = bits per second; both sides must match (commonly 115200 or 9600).
  • Oversampling (8× or 16×): the receiver samples each bit multiple times and takes a majority vote for noise immunity.
  • Parity (even/odd): a check bit that detects a single-bit error but cannot correct it.
"8-N-1" The terminal setting you'll use: 8 data bits, No parity, 1 stop bit. Characters are ASCII: 'A'=65, 'K'=75.

Lab 3.1 — Transmitting a byte

Send the letter 'K' (ASCII 75) once per second. Setup PA2 to alternate-function 7, configure USART2, then write to DR.

#define UART_DATA_ASCII (75U)   // 'K'

// PA2 -> alternate function 7 (USART2_Tx)
GPIOA->MODER &= ~GPIO_MODER_MODER2;
GPIOA->MODER |= (0b10 << GPIO_MODER_MODER2_Pos);   // 10 = alternate
GPIOA->AFR[0] |= (7 << GPIO_AFRL_AFSEL2_Pos);      // AF7

// USART2 setup
USART2->CR1 |= USART_CR1_UE;      // enable
USART2->CR1 &= ~USART_CR1_M;     // 8 data bits
USART2->CR2 &= ~USART_CR2_STOP;  // 1 stop bit
USART2->BRR = 139;               // baud divisor (115200 @ 16MHz)
USART2->CR1 |= USART_CR1_TE;      // enable transmitter

while(1){
    USART2->DR = UART_DATA_ASCII;
    DELAY_SEC;
}
Seeing the output Open a serial terminal (PuTTY, Tera Term, CoolTerm, or serialterminal.com), connect to "STMicroelectronics ST-Link Virtual COM Port", set 115200 baud, 8-N-1. You should see a stream of K.

Strings in C & sprintf

A C string is a char array ending in the null terminator '\0'. char s[]="Hi" auto-sizes to 3 (H, i, \0).

To send a whole string, loop until the null terminator, waiting for TXE before each byte:

static void UART2_TxString(char strOut[]){
    for(uint8_t idx=0; strOut[idx] != '\0'; idx++){
        while((USART2->SR & USART_SR_TXE) == 0);  // wait until Tx ready
        USART2->DR = strOut[idx];
    }
}
Why wait for TXE? TXE=1 means the data register is empty and it's safe to write the next byte. Writing before that would overwrite a byte still being sent. Writing to DR clears TXE automatically.

sprintf formats values into a string buffer so you can send numbers:

char buf[50];
sprintf(buf, "Sensor data = %d\n", sensorValue);   // %d decimal
sprintf(buf, "O2: 0x%x", oxygen);                  // %x hex, %c char
UART2_TxString(buf);

Labs 3.3 / 3.4 — Receiving & echo

Enable the receiver (RE) and set up PA3 as AF7. Poll RXNE; when set, DR holds the received byte.

USART2->CR1 |= USART_CR1_RE;   // enable receiver

if((USART2->SR & USART_SR_RXNE) != 0){
    char c = USART2->DR;   // reading DR clears RXNE
    sprintf(buf, "You've entered: %c\n\r", c);   // echo (Lab 3.4)
    UART2_TxString(buf);
    if(c == '1') GPIOB->ODR |= GPIO_ODR_OD6;   // green LED on
    else        GPIOB->ODR &= ~GPIO_ODR_OD6;
}
Remember for the exam Tx side waits on TXE; Rx side waits on RXNE. Reading DR clears RXNE; writing DR clears TXE. These flags come back in Ch 5 as interrupt sources.

Chapter 4 — ADC (Analog-to-Digital Conversion)

Sensors output continuous analog voltages; the CPU only understands digital numbers. The ADC bridges them.

ADC fundamentals

  • Analog = continuous (any voltage). Digital = discrete steps.
  • Conversion process: Sample & Hold → Quantizer → Encoder.
  • Resolution (bits): more bits = finer steps. STM32F411RE = 12-bit → values 0–4095.
  • Vref: the voltage that maps to the maximum code (3.3 V here).
  • Sample time: how long the input is sampled — longer is more accurate for high-impedance sources.
The conversion formula — memorize this
Digital = floor[ Vin / Vref × (2n − 1) ]
Example: 12-bit, Vref=3.3 V, Vin=2.14 V → floor(2.14/3.3 × 4095) = floor(2655.2) = 2655.

ADC on STM32F411RE & its registers

One ADC module (ADC1), 12-bit SAR type, up to 16 external channels. Channels map to pins: PA0→ch0, PA1→ch1, … PA7→ch7 (the "Additional Functions" column of the datasheet).

Lab 4.1 — Reading the potentiometer

Potentiometer on PA4 (channel 4). Read it by polling; light PA5 when the value crosses the midpoint (2048).

RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
RCC->APB2ENR |= RCC_APB2ENR_ADC1EN;    // ADC clock is on APB2!

// PA4 as analog (11)
GPIOA->MODER &= ~GPIO_MODER_MODER4;
GPIOA->MODER |= (0b11 << GPIO_MODER_MODER4_Pos);

ADC1->CR2   |= ADC_CR2_ADON;              // enable ADC
ADC1->SMPR2 |= ADC_SMPR2_SMP4;            // 480-cycle sample time
ADC1->SQR1 &= ~ADC_SQR1_L;               // L = 0 -> 1 conversion
ADC1->SQR3 &= ~ADC_SQR3_SQ1;
ADC1->SQR3 |= (4 << ADC_SQR3_SQ1_Pos);   // first conversion = channel 4

while(1){
    ADC1->CR2 |= ADC_CR2_SWSTART;             // start
    while((ADC1->SR & ADC_SR_EOC) == 0);   // wait for result
    if(ADC1->DR > 2048) GPIOA->ODR |= GPIO_ODR_OD5;
    else               GPIOA->ODR &= ~GPIO_ODR_OD5;
}
Slide typo to watch The register summary table (4.pdf p.28) prints "MODER5" for "set PA4 to analog" — that's a typo. The correct bit is MODER4 (the assignment code on p.29 uses GPIO_MODER_MODER4). Trust the code.

NTC thermistor — turning volts into °C

An NTC thermistor's resistance decreases as temperature rises. Wired as a voltage divider (R16 = 10 kΩ fixed, R23 = MF52 NTC), the ADC reads the midpoint voltage.

RNTC = Rx × ( Vout / (Vcc − Vout) )

Then convert resistance to temperature. Two models exist — the Beta equation (preferred in embedded for simplicity) and the more accurate Steinhart-Hart:

T = (β · T0) / ( T0 · ln(RNTC/R0) + β ) [Kelvin]

Lab 4.2 — Reading temperature

Print temperature every second. Uses PA0 (channel 0) as analog input and floating-point math — which means you must enable the FPU first.

#define VREF 3.3f
#define VCC  3.3f
#define ADC_MAXRES 4095.0f
#define RX   10000.0f
#define R0   10000.0f
#define T0   298.15f    // 25°C in Kelvin
#define BETA 3950.0f

float adc_voltage = (ADC1->DR * VREF) / ADC_MAXRES;
float r_ntc = RX * adc_voltage / (VCC - adc_voltage);
float temperature = ((BETA * T0) / (T0*log(r_ntc/R0) + BETA)) - 273.15f;
sprintf(buf, "Temperature = %d millidegree Celcius\n", (int32_t)(temperature*1000.0f));

The Floating-Point Unit (FPU)

The Cortex-M4 has dedicated hardware for IEEE-754 single-precision float math: 5–10× faster, more accurate, lower power, and no bulky software math library. But it boots disabled.

Enable the FPU before any float math Set full access for coprocessors 10 and 11 (bits 20–23 of CPACR) to 0b11 each: 
SCB->CPACR |= (0b1111 << 20);   // CP10 & CP11 = full access
__asm volatile("dsb");        // data sync barrier
__asm volatile("isb");        // instruction sync barrier
Forget this and float code will hard-fault.

LDR — Light Dependent Resistor (Lab 4.3)

An LDR (photoresistor) is a passive part whose resistance decreases as light increases. Same voltage-divider trick as the NTC (R16 = 10 kΩ fixed, R22 = GL5528 LDR):

RLDR = Rx × ( Vout / (Vcc − Vout) )

Lab 4.3 prints Light intensity = … Lux every second and turns the blue LED on when the LDR is covered (dark). It reuses the exact ADC + FPU + sprintf pattern from Lab 4.2.

Chapter 5 — Interrupts

The payoff chapter. Instead of the CPU wasting time polling, an interrupt lets hardware call you only when something happens.

Why interrupts?

Definition An interrupt is a signal that temporarily stops the CPU's current task and forces it to run a special function — the Interrupt Service Routine (ISR). When the ISR finishes, the CPU resumes exactly where it left off.

The slides' analogy: a boy doing homework while waiting for food.

  • No doorbell (polling) — he keeps running to the door to check. Wastes time and energy, and he might miss homework deadlines.
  • With a doorbell (interrupt) — he focuses on homework and only gets up when the bell rings. The bell = interrupt source, its ring = interrupt request.
Interrupt vs polling Polling: CPU constantly checks (simple, wasteful). Interrupt: CPU sleeps/does other work and reacts on demand (efficient, lower power). In interrupt code the while(1) loop is usually empty.

The NVIC (Nested Vectored Interrupt Controller)

The NVIC is hardware inside the Cortex-M4 that manages all interrupts. It decides which interrupts are enabled, their priority, and supports nesting (a higher-priority interrupt can interrupt a lower one).

General flow

  1. Peripheral triggers an interrupt request (IRQ).
  2. NVIC detects it.
  3. If enabled and nothing higher-priority is pending, the NVIC:
    1. saves the current program state (PC, PSR…) to the stack,
    2. jumps to the ISR address from the vector table.
  4. After the ISR, an exception return restores the saved state.
Priority in practice If the CPU is in a high-priority ISR (A) and a lower one (B) fires, B waits until A finishes. If the CPU is in a low-priority ISR (B) and a higher one (A) fires, A preempts B (nesting); when A returns, B resumes. Lower priority number = higher urgency.

Enabling interrupts (CMSIS) & writing an ISR

You enable an interrupt with a CMSIS function and the peripheral's IRQ number (from the vector table, "Position" column of RM0383 Table 37). USART2's IRQ number is 38.

CMSIS functionDoes
NVIC_EnableIRQ(IRQn)enable an interrupt
NVIC_DisableIRQ(IRQn)disable it
NVIC_SetPriority(IRQn, p)set its priority
NVIC_SetPendingIRQ / ClearPendingIRQforce / clear a pending request
NVIC_EnableIRQ(38);              // by number…
NVIC_EnableIRQ(USART2_IRQn);    // …or the readable macro (preferred)
ISR naming is fixed by CMSIS An ISR is a void function with no arguments and no return value, and its name must be exactly <Acronym>_IRQHandler: 
void USART2_IRQHandler(void){
    // handle the interrupt, clear the source
}
The name links your function into the vector table so the CPU finds it. A typo = your ISR never runs.

Lab 5.1 — UART Rx interrupt

Convert the polled receive lab into an interrupt-driven one. The while(1) becomes empty; the LED logic moves into the ISR.

How to trigger it: per the reference manual, when a byte arrives and RXNEIE (Rx-not-empty interrupt enable, in CR1) is set, an interrupt is generated.

void USART2_IRQHandler(void){
    if((USART2->SR & USART_SR_RXNE) != 0){
        if(USART2->DR == '1') GPIOA->ODR |= GPIO_ODR_OD5;
        else                   GPIOA->ODR &= ~GPIO_ODR_OD5;
    }
}
// in main, after normal USART setup:
USART2->CR1 |= USART_CR1_RXNEIE;   // enable Rx interrupt
USART2->CR1 |= USART_CR1_RE;
NVIC_EnableIRQ(USART2_IRQn);
NVIC_SetPriority(USART2_IRQn, 0);
while(1){}   // empty!

Lab 5.2 — ADC End-of-Conversion interrupt

Same idea for the ADC. Per the manual, when a conversion completes and EOCIE (in CR1) is set, an interrupt fires. The while(1) keeps only "start conversion + delay ~100 ms"; the read-and-decide logic moves into the ISR.

void ADC_IRQHandler(void){
    if((ADC1->SR & ADC_SR_EOC) != 0){
        if(ADC1->DR <= 2048) GPIOA->ODR |= GPIO_ODR_OD5;
        else                 GPIOA->ODR &= ~GPIO_ODR_OD5;
    }
}
// setup:
ADC1->CR1 |= ADC_CR1_EOCIE;   // enable EOC interrupt
NVIC_EnableIRQ(ADC_IRQn);
NVIC_SetPriority(ADC_IRQn, 0);
Pattern recognition Every "convert polling to interrupt" lab is the same three edits: (1) enable the peripheral's interrupt-enable bit (RXNEIE / EOCIE), (2) NVIC_EnableIRQ the right IRQ, (3) move the reaction code into the correctly-named _IRQHandler.

EXTI — External Interrupts (from GPIO pins)

The EXTI (External Interrupt/Event Controller) lets a GPIO pin raise an interrupt on an edge — so a button press interrupts the CPU instead of being polled.

Key components

  • Edge detect circuit — senses a transition on the input line.
  • Trigger selection (RTSR / FTSR) — rising edge, falling edge, or both.
  • Interrupt mask register (IMR) — enables/disables the EXTI line's interrupt.
  • Pending register (PR) — flags which line fired; you must clear it in the ISR by writing 1.
Line ↔ pin mapping 21 EXTI lines. Lines 0–15 map to GPIO pin numbers 0–15. A line can take that pin from any port, but only one port at a time — chosen in the SYSCFG_EXTICR1..4 registers. Example: EXTI4 can source from PA4, PB4, PC4… (0001 = port B).
Shared ISRs Not every line has its own vector. Lines 5–9 share EXTI9_5_IRQHandler; lines 10–15 share EXTI15_10_IRQHandler. Inside a shared ISR you must check the PR to see which line actually fired. Lines 0–4 have their own dedicated handlers (EXTI0_IRQHandler … EXTI4_IRQHandler).

Lab 5.3 — EXTI interrupt (button)

Button on PB4 → light PA5, using EXTI line 4 instead of polling. Because SYSCFG is involved, enable its clock too (RCC_APB2ENR_SYSCFGEN).

Setup checklist (from the reference manual)

  1. Enable the EXTI line in IMR (EXTI->IMR |= EXTI_IMR_MR4).
  2. Choose the edge in RTSR and/or FTSR.
  3. Route the pin's port in SYSCFG_EXTICR (EXTI4 lives in EXTICR[1]; write 0001 for port B).
  4. NVIC_EnableIRQ(EXTI4_IRQn).
void EXTI4_IRQHandler(void){
    if((EXTI->PR & EXTI_PR_PR4) != 0){
        if((GPIOB->IDR & GPIO_IDR_ID4) == 0)
            GPIOA->ODR |= GPIO_ODR_OD5;
        else
            GPIOA->ODR &= ~GPIO_ODR_OD5;
        EXTI->PR |= EXTI_PR_PR4;   // clear pending: write 1!
    }
}
// setup:
RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;
EXTI->IMR  |= EXTI_IMR_MR4;                  // unmask line 4
EXTI->RTSR |= EXTI_RTSR_TR4;                 // rising edge
EXTI->FTSR |= EXTI_FTSR_TR4;                 // falling edge (both)
SYSCFG->EXTICR[1] &= ~SYSCFG_EXTICR2_EXTI4;
SYSCFG->EXTICR[1] |= (0b0001 << SYSCFG_EXTICR2_EXTI4_Pos);  // port B
NVIC_EnableIRQ(EXTI4_IRQn);
NVIC_SetPriority(EXTI4_IRQn, 0);
The #1 EXTI mistake Forgetting to clear the pending bit (EXTI->PR |= EXTI_PR_PRx) at the end of the ISR. If you don't, the interrupt re-fires forever and the program appears frozen. You clear it by writing 1, not 0.

Running them Create an empty (register-level, no-HAL) STM32F411RE project in STM32CubeIDE or Keil, replace main.c with the lab's file, build, and flash over the on-board ST-Link. Serial labs use 115200 baud, 8-N-1 on the ST-Link Virtual COM Port. Full steps are in labs/README.txt.
Before you trust the output Register macro spellings vary slightly by CMSIS header version (e.g. GPIO_PUPDR_PUPD4 vs PUPDR4) — check stm32f4xx.h if one won't compile. Lab 4.3's SLOPE/OFFSET are the reconstructed GL5528 constants; verify them against your slide.
